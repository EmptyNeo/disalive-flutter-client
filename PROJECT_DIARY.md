# Дневник проекта Disalive

## 2026-10-13 — первичное изучение

Проект: Flutter-приложение для Android и iOS. Это рабочие заметки для будущих задач; обновлять при изменении архитектуры. Выводы основаны на чтении исходников, без запуска приложения.

### Структура и зависимости

- `lib/app/di/di.dart` — регистрация зависимостей через `get_it`; `lib/app/theme/` — тема.
- `lib/domain/` — модели, интерфейсы репозиториев, сервисы, ошибки; `lib/data/repositories/` — реализации; `lib/data/network/` — API-адреса и сертификат.
- `lib/presentation/` — экраны, виджеты, BLoC/Cubit. Также есть `android/`, `ios/`, `assets/` и `test/` с тестами.
- `pubspec.yaml`: пакет `disalive` версии `1.0.0+1`, Dart SDK `^3.10.8`, публикация отключена. Важные пакеты: `flutter_bloc`, `bloc`, `get_it`, `dartz`, `http`, `dio`, `web_socket_channel`, `flutter_secure_storage`, Firebase. В активах есть `assets/certs/globalsign.pem`.

### Запуск и главный экран

`lib/main.dart`: инициализация Flutter, Firebase, push-уведомлений, `CertHttpOverrides` и DI; затем `runApp(DisaliveApp)`. Загрузка emoji запускается без ожидания. `DisaliveApp` предоставляет `ThemeCubit` и `AuthBloc` с `CheckAuthStatus`. По состоянию авторизации показывает Splash, Home или Login; также задаёт именованные маршруты Home, Login, Register, ResetPassword.

`lib/presentation/features/home/home_screen.dart`: локально создаёт BLoC для WebSocket-сервера, профиля, чатов, запросов, сообщений, участников, сессий, GIF, стикеров и реакций. Сразу отправляет `ConnectToChatServer`, `GetProfile`, `GetChats`, `GetRequests(true)`. При соединении запускает подписки BLoC на события. Профиль управляет состояниями загрузки/ошибки/контента. `PageView` содержит чаты, настройки, профиль; нижнее меню и кнопка создания чата расположены поверх. Есть счётчик непрочитанных и признак переподключения.

### HTTP-запросы

Путь запроса: событие UI → BLoC → интерфейс репозитория → реализация репозитория → `HttpClientService`. Пример: `ChatRepositoryImpl.get()` вызывает `postFormData` для `chats/get.php` и преобразует `data` в `List<Chat>`.

- `HttpClientService` — lazy singleton из `app/di/di.dart`. По умолчанию использует `UserAgentClient(http.Client())`, который добавляет `User-Agent` и `Accept: application/json`; клиент можно передать в конструктор.
- Методы: `postFormData<T>` для URL-encoded POST, `postMultipart<T>` для POST с файлами, `get<T>` для GET с query. Значения параметров переводятся в строки.
- По умолчанию сервис читает `keySession` из `SecureStorageService` и кладёт его в форму, multipart-поля либо query. При отсутствии ключа возвращает `UnauthorizedFailure` до отправки. Вход использует `requireAuth: false`; `AuthRepositoryImpl` сохраняет полученный ключ.
- `ApiType.v1` → `https://disalive.ru/v1/`, `ApiType.php` → `https://disalive.ru/php/`. `CertHttpOverrides` добавляет сертификат из активов к доверенным корням `dart:io`.
- Ожидается JSON с `success`, `data` и при ошибке `error`/`errors`. Возврат — `Either<Failure, T>`: `Right(fromJson(data))` либо `Left`. Если `data` отсутствует при успехе, `fromJson` получает `{'success': true}`.
- При `success: false` коды 401/403 дают `UnauthorizedFailure` (может вызываться `onUnauthorized`), 422 с картой ошибок — `ValidationFailure`, 500 — `ServerFailure`, остальные — `ClientFailure`. Ошибки парсинга дают `ParsingFailure`, исключения при отправке — `NetworkFailure`.
- Явные таймауты и повторы не заданы. `get()` дописывает `keySession` в переданную карту `queryParams`, если она была передана. WebSocket и `WsEventBus` обрабатывают события реального времени отдельно. `dio` встречается в `file_item.dart` для файлов.
