# Disalive

Disalive — мобильное приложение для общения на Android и iOS. В нём есть личные и групповые чаты, серверы с каналами и ролями, обмен файлами и стикерами, приглашения и голосовые и видеозвонки. Этот репозиторий содержит исходный код **мобильного клиента** на Flutter.

## Возможности

- Личные и групповые чаты: сообщения, ответы, реакции, вложения и локальные черновики.
- Серверы: текстовые и голосовые каналы, категории, роли, права доступа и приглашения.
- Просмотр фотографий, видео, файлов, аудио и ссылок из чата.
- Звонки на LiveKit с микрофоном, камерой и демонстрацией экрана. На Android активный звонок поддерживает режим «Картинка в картинке».
- Уведомления о событиях через Firebase Cloud Messaging (FCM).

## Технологии и структура

| Часть | Используется |
| --- | --- |
| Интерфейс | Flutter, Dart, виджеты Cupertino |
| Состояние экранов | `bloc`, `flutter_bloc` |
| Внедрение зависимостей | `get_it` |
| Запросы и события | `http`, `dio`, `web_socket_channel` |
| Звонки | `livekit_client`, WebRTC, TURN |
| Уведомления | Firebase Cloud Messaging, локальные уведомления |
| Данные на устройстве | `flutter_secure_storage`, `shared_preferences`, файлы приложения |

Код разделён на `lib/presentation/` (экраны и BLoC), `lib/domain/` (модели и контракты) и `lib/data/` (репозитории и работа с сетью). Регистрация зависимостей находится в [`lib/app/di/di.dart`](lib/app/di/di.dart).

## Какие данные обрабатывает клиент

Приложение отправляет на сервер Disalive данные, необходимые для выбранных пользователем действий: данные входа, сообщения, вложения, настройки чатов и серверов. Запросы API направляются на `https://disalive.ru`, события чатов передаются через `wss://disalive.ru:8081`. Сетевые адреса API можно проверить в [`domain.dart`](lib/data/network/domain.dart) и [`chat_server_repository_impl.dart`](lib/data/repositories/chat_server_repository_impl.dart).

Для звонков клиент получает токен у сервера Disalive и подключается к `wss://livekit.disalive.ru:4443`; при необходимости WebRTC использует TURN. Камера, микрофон и демонстрация экрана задействуются для функций звонка. Для push-уведомлений используется FCM: при разрешённых уведомлениях клиент получает push-токен и может передать его серверу Disalive. Отдельный SDK аналитики в зависимостях проекта не подключён.

Ключ сессии хранится в защищённом хранилище устройства через [`SecureStorageService`](lib/domain/services/secure_storage_service.dart). Черновики сообщений и позиция чтения чата сохраняются локально; черновики удаляются при выходе из аккаунта. Изображения, вложения и предпросмотры ссылок могут загружаться с адресов, указанных в сообщениях или ответах сервера, в том числе со сторонних ресурсов.

**Границы проверки:** этот репозиторий показывает поведение мобильного клиента. Серверная часть, настройки инфраструктуры и правила хранения данных на сервере здесь не опубликованы. Исходный код также не доказывает, что установленная сборка была получена именно из этого коммита. Для самостоятельной проверки можно собрать приложение из исходников и наблюдать его сетевой трафик.

## Запуск из исходников

Понадобятся Flutter с Dart SDK `^3.10.8`, Android Studio или Xcode и доступ к работающему серверу Disalive. Некоторые функции требуют настройки Firebase для соответствующей платформы. Без сервера вход, переписка и звонки работать не будут.

```sh
flutter pub get
flutter run
```

Проверка кода:

```sh
flutter analyze
flutter test
```

Перед публикацией проверьте конфигурацию Firebase. TURN credentials клиент получает от backend вместе с токеном звонка; общий секрет хранится только на стороне сервера. Постоянные секреты нельзя безопасно хранить в мобильном приложении. Уже использованные постоянные TURN credentials нужно отозвать при переходе на временные.
